# interaction-flow.md

## 상호작용 원칙

각 도메인은 다른 도메인의 데이터를 직접 조작하지 않는다. 대신 "요청 신호"를 보내고, 요청받은 도메인이 자신의 데이터를 스스로 갱신한다.

## 핵심 흐름 — 추격자 시나리오 기준

### 흐름 1. 선택 → 관계 변경

```
[서사 도메인]
  플레이어가 선택지 A를 고른다
  → "설매에게 호감도 +2 적용해줘" 요청을 [관계 도메인]에 전달
[관계 도메인]
  요청받은 값(+2)만큼 설매의 호감도 수치를 갱신
  → 갱신 후 상태(호감/중립/불신/적대)를 재판정
  → [서사 도메인]에 "현재 설매는 호감 상태"라고 응답
[서사 도메인]
  응답받은 상태에 맞는 다음 대사를 출력
```

### 흐름 2. 임계점 도달 → 성장 반영

```
[관계 도메인]
  호감도 갱신 결과 임계점(+5) 도달을 감지
  → [서사 도메인]에 "임계점 도달" 신호 전달
[서사 도메인]
  결과 이벤트(초식 전수 장면) 대사를 출력
  → "삼류로 경지 상승해줘" 요청을 [캐릭터/성장 도메인]에 전달
[캐릭터/성장 도메인]
  경지값을 평민 → 삼류로 갱신
  → 무공 목록에 "일섬" 추가
  → 갱신 완료를 [서사 도메인]에 응답
[서사 도메인]
  성장 확인 연출(예: 상태 변화 알림)을 출력
```

### 흐름 3. 정적 데이터 참조 — 세계관/인물 정보

```
[서사 도메인]
  시나리오 시작 시 [세계관/콘텐츠 데이터 도메인]에 "취선루 배경 정보", "설매 기본 정보" 요청
[세계관/콘텐츠 데이터 도메인]
  저장된 정적 데이터를 그대로 반환 (변경 없음, 조회만 발생)
```

### 흐름 4. 사망 엔딩 — 도메인 간 통신 중단

```
[서사 도메인]
  선택지 D(또는 B-사망, C-패배, C-배신 처단) 도달
  → 관계/성장 도메인에 어떤 요청도 보내지 않는다
  → 즉시 엔딩 처리 (도메인 간 상호작용 없이 서사 도메인 내부에서 종료)
```

### 흐름 5. 진행 상태 저장 (세이브 도메인 포함 가정 시)

```
[진행 상태 도메인]
  일정 시점(예: 선택 완료 직후)에 아래 도메인들에 "현재 값 알려줘" 요청
    → [캐릭터/성장 도메인]: 현재 경지
    → [관계 도메인]: 현재 호감도
    → [서사 도메인]: 현재 분기 위치
  → 응답받은 값을 하나의 스냅샷으로 저장
```

## 상호작용 요약표

| 발신 도메인 | 수신 도메인 | 전달 내용 | 발생 시점 |
|---|---|---|---|
| 서사 | 관계 | 호감도 증감 요청 | 선택지 선택 시 |
| 관계 | 서사 | 갱신된 상태(호감/중립/불신/적대) | 호감도 갱신 직후 |
| 관계 | 서사 | 임계점 도달 신호 | 수치가 임계점 넘을 때 |
| 서사 | 성장 | 경지 상승 요청 | 임계점 도달 이벤트 처리 시 |
| 성장 | 서사 | 갱신 완료 응답 | 경지 갱신 직후 |
| 서사 | 세계관 데이터 | 배경/인물 정보 조회 | 시나리오 시작 시 |
| 진행상태 | 성장/관계/서사 | 현재 값 조회 | 저장 시점 (포함 시) |

---

**완료 체크:** 3단계에서 정의한 각 도메인의 요구사항이 실제로 어느 시점에 어느 도메인과 통신하는지 빠짐없이 표현됨. 사망 엔딩처럼 "상호작용이 발생하지 않는 경우"도 명시적으로 문서화됨.
